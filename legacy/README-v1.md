# zine-maker · 给不写代码、不画画的人看的说明书

你只要记住一件事：**把照片放一个文件夹、把想说的话写一个文件，然后跑一句话，就得到一本能打印的小册子。**

> **已安装**：这个 skill 已经装进 WorkBuddy（用户级 `~/.workbuddy/skills/zine-maker/`），当前为启用状态；已用示例素材和你的 14 张真实照片分别跑通。
>
> **当前状态（2026-11-04）**：视觉回到第一版（暖纸、波点、圆形/椭圆裁切、白边贴纸、手绘线、荧光黄绿），
> 交互保留后面加的东西（先摆照片、分组、定封面封底、原话不改写）。
> 中间试过的「淡色极简 / 三个方向 / 组合系统」已归档，不再是生成依据。
>
> **最省事的用法是根本不用记命令**：直接在对话里说一句人话就行，例如「把 `~/Desktop/我的照片` 做成 zine」。
> 想自己决定哪几张照片是一件事、哪张当封面、每页写什么，就说「1、5、12 是一组，叫……，封面用 08」，
> 或者用摆台把照片摆好。你的原话会原样印上去，不会替你写。
>
> 想手动执行、或要固定参数复现，才需要用下面的命令。

---

## 0. 先搞懂我们在做什么（30 秒）

zine 不是杂志。杂志有栏目、目录、编辑部；zine 是「一个人把自己拍到的东西整理成一叠纸」。
所以自动排版这件事，不是让电脑替你做设计，而是让它替你做**三件机械的活**：

1. **分配**：这一页放几张图、图多大、那句话放哪儿。
2. **统一**：每页都有的小标签、同一种圆点、同一种纸色，让 12 页看起来是一套东西。
3. **折纸顺序**：打印时第 1 页旁边要放最后一页，不然折起来页码全乱。

审美判断已经事先写进规矩里了，你不用现场判断。

## 1. 准备两样东西

**(A) 一个照片文件夹**，比如 `my-trip/`，里面放 jpg / png，文件名按顺序命名（`01.jpg`、`02.jpg`…）。
不需要先修图，脚本会统一调色、裁切、加白边。

**(B) 一个文字文件** `texts.json`，长这样：

```json
{
  "title": "日子的边角",
  "subtitle": "a small zine about ordinary days",
  "issue": "第 01 期 · 2026 秋",
  "author": "一个普通人",
  "labels": ["FRAME 01", "FRAME 02", "FRAME 03"],
  "texts": [
    "周日的光会晚一点到。",
    "窗台上那串东西挂了三年，羽毛被晒得发白。",
    "后来搬了家，这些角度就再也拍不到了。"
  ]
}
```

- `texts`：一句一句写，**不要写长文章**。超过 80 字会被自动切成短句。
- `labels`：每页顶部轮流出现的小字。这是「记录感」的来源，随便写几个就够。
- 其他字段可以都不填，会用中性默认值。
- **别照抄示例里的地名、日期、期号、作者**：你没给的话，脚本不会替你编；示例只是演示格式。

> 不想写 json？建一个 `texts.txt`，一行一句也行。

## 2. 跑一句话

在终端里粘贴（把三处路径换成你自己的）：

```bash
python3 ~/.workbuddy/skills/zine-maker/scripts/make_zine.py \
  --images /你的路径/my-trip \
  --texts /你的路径/texts.json \
  --out /你的路径/out \
  --style field
```

屏幕上会打印「第 1 页放什么、第 2 页放什么」，这就是**版式清单**，你能看懂。

想换味道，把最后 `--style field` 换成：

| 值 | 长什么样 |
|---|---|
| `field` | 采集 / 散步记录（默认）：白纸、贴纸小图、圆点、荧光黄绿、时间地点小字 |
| `colorblock` | 色块拼贴：高饱和纯色和照片各占一半，更跳 |
| `artbook` | 艺术家书：斑点纸、一页只放一个东西、大量留白 |
| `xerox` | 黑白复印机：死黑死白、打字机字、粗糙感 |
| `riso` | 荧光双色套印：粉 + 蓝、粗标题 |

想让两次结果一模一样，加 `--seed 7`；换个数字会换一套版式组合（图片不变）。

## 2b. 想自己摆：先摆，后排（推荐）

**为什么多这一步**：一次给十几张照片，里面往往有几张是同一个下午、同一顿饭、同一段路。
它们应该挨在一起，才讲得成一件小事。而「哪几张算一件事、给这组起什么名、哪张配当封面」
这些决定，本来就是做 zine 最好玩的部分——不能让电脑替你做。

所以分工是：**你负责摆和说，电脑负责印和装订**（纸色、字体、裁切、页数、折纸顺序）。

有三种摆法，随便挑一种：

1. **说人话**——「02、08、13、14 是一组，01、05、12 是另一组，封面用 08，标题写……，09 那张不要」。
2. **摆台**——打开 `摆台.html`，照片摊在桌面上：改组名、拖顺序、点掉不要的、设封面和最后一页，
   点「复制我摆好的结果」粘回对话，或点「下载 story.json」把文件给我。
3. **直接写 `story.json`**——字段见下，改完发我。

摆完之后跑（只多一个 `--story`）：

```bash
python3 ~/.workbuddy/skills/zine-maker/scripts/make_zine.py \
  --images /你的路径/my-trip \
  --story /你的路径/story.json \
  --out /你的路径/out \
  --style field --seed 7
```

脚本会照着摆：同一组的照片连着出现、`dropped / ungrouped` 里的不参与、你指定的封面图/末页图生效、
每组的 `note` 原样放在该组第一页。

| 字段 | 管什么 |
|---|---|
| `groups[].images` | 这一组有哪些照片（写 `08` 或 `08.jpg` 都行） |
| `groups[].name` | 组名，会变成这一组页面上的小标签 |
| `groups[].note` | 这组想说的一句话，**原样印，不改字** |
| `order` | 组的先后顺序 |
| `dropped` / `ungrouped` | 划掉、先不用的照片 |
| `cover.image / title / sub / layout` | 封面图、封面文字、封面性格 |
| `back.image / text / layout` | 末页图、末页文字、末页性格 |
| `breath` | 想要几页留白 |

`cover.layout`：`photo_full`（满版照片，默认）/ `paper_collage`（错落贴纸）/ `plain`（只有纸）。
`back.layout`：`breath`（纯留白，默认）/ `photo`（带图）。

**两条硬规矩**：

- 每个文字字段要带来源标记：`user_verbatim`（你的原话）、`user_confirmed_guess`（我猜但你确认过）、
  `unfilled`（没填）。标了「待确认」的我猜的组名和文案**不会印**，宁可留白也不替你写。
- 没填标题，封面就不显示标题；没填文案，那页就空着。**留白是故意的，不是漏排。**
  地名、日期、期号、作者、印量一律不替你编。

脚本另外会写一份 `文字来源对照.txt`，把册子上每一个字标出来是「你的原话」还是「版式自带的编号」。

## 3. 你会拿到什么

| 文件 | 干什么用 |
|---|---|
| `zine.html` | **先看这个**。浏览器打开，一页一页往下翻 |
| `版式清单.txt` | 大白话：第几页放几张图、哪句话 |
| `plan.json` | 完整版式计划，可以手动改某一页的 `skeleton`（版式名） |
| `zine.pdf` | 阅读版，A5 |
| `imposed.pdf` | **打印用这个**，页序已按折纸顺序排好 |
| `README.txt` | 打印设置，贴在打印机旁边看 |
| `文字来源对照.txt` | **用了 `--story` 才有**：册子上每个字来自哪里，逐条可回查 |

## 4. 打印（三件事，缺一不可）

1. 双面打印，翻面方式选**短边翻转**
2. 缩放选 **100% / 实际大小**，千万别选「适合页面」
3. **关掉**打印机自带的「小册子 / booklet」模式（我们已排好序）

先只打第一张，对折一下，看封面和封底是不是在同一张纸的两面。对了再打整本。
整叠对折，沿书脊订两枚订书钉，完成。

**为什么页数总是 12 / 16 这种数？** 一张纸对折正好提供 4 页，所以总页数必须是 4 的倍数。
不够时脚本会补一页「呼吸页」，不会给你一张尴尬的白纸。

## 5. 不满意怎么改（按从易到难）

| 想改什么 | 怎么做 |
|---|---|
| 换一套版式组合 | 换 `--seed` 数字 |
| 换整体味道 | 换 `--style` |
| 照片顺序 | 改文件名排序 |
| 某句话太长了 | 直接改 texts，短句比长文更像 zine |
| 某一页想换版式 | 打开 `plan.json`，把那页的 `skeleton` 改成别的名字，重跑 |
| 想加一种新风格 | `scripts/make_zine.py` 里的 `STYLES` 字典照着加一份 |

版式名字都在 `references/layout-catalog.md` 里，每个都写了「几张图、放哪儿、多少字」。

## 6. 这些规矩是从哪来的

不是我拍脑袋定的。你给的 20 张 zine 参考图，我拼成总览又放大看了 10 张，逐条数出：

- 纸永远是近白暖或斑点米黄，不是纯白
- 一页最多 1 个高饱和彩色
- 照片大多是**小尺寸、带白边、像贴上去的**，不是张张满版
- 圆形 / 椭圆 / 圆角裁切反复出现
- 每页都有极小的「地点 + 日期 + 时间」标签
- 手写、手绘线、编号徽章、时间戳、清单混排
- 留白很多，一页只讲一件事
- 跨页是基本单位，中心两页要成对设计
- 几乎没有长文——所以脚本会主动把长文切碎

完整清单在 `references/zine-dna.md`，里面还列了**反例**：之前找的 6 张「zine 模板」其实是商业杂志模板（条码、目录、双栏长文），已明确禁止。

## 7. 已知的小毛病

- PDF 因为内嵌照片会偏大（十几 MB）。**分享 / 预览用 HTML**，要小文件就用 macOS 预览打开 PDF 后「文件 → 导出 → 缩小文件大小」。
- 同一张照片在不同页以不同裁切出现，是这批参考图的特征；但**全本最多 2 次**，第二次会换成别的角色
  （封面 / 中心跨页 ≠ 组内小图），并在 `版式清单.txt` 里点名，你可以说去掉。
- 圆点、手绘线的位置是程序生成，不是设计师手摆，追求「不精确」但不会乱到离谱。
- `--story` 模式下页数由「你分了几组 + 要几页留白」决定，可能是 8 页而不是 12/16 页；
  这样 14 张照片能各出现一次，不会为了凑页数反复用同一张。
- 摆台已经能做分组、顺序、取舍、封面和末页；**拖拽换页 / 拖拽换版式**还没做。
  `plan.json` 已预留成前后端契约，后续做交互产品不用重写渲染引擎。
