# 交互机制：让创造的乐趣留在用户手里

> **用户定义（2026-11-04 21:27 原话）**：
> 「给一个有强烈表达欲，但没有设计功底的人做出 zine，但你又不能剥夺它创造的乐趣」。

---

## 一、先承认上一版方案仍然不对

上一版提了「5 步陪聊」：AI 分组 → AI 问 → 用户答 → AI 排版 → 用户挑样张。
看起来有人了，其实**用户全程在「回答」和「挑选」，创造权还是在 AI 手里**。
一个表达欲强的人不需要被采访，她需要的是**一张桌面和一盒已经裁好的纸片**。

> 角色重分：**AI 负责「印」和「装订」，用户负责「摆」和「说」。**
> 不是代笔写日记，是把纸、色、字体、装订这些需要功底的活做掉，把取舍留给本人。

---

## 二、核心形态：一叠可以自己摊开摆弄的卡片

依据：用户喜欢的 #4 就是「印好的小卡片摊在桌上」。
把它变成交互形态——每页是一张**直角小卡片**，用户能看到全部卡片、能改顺序、能抽掉一张、能把两张挪到一起。

| 用户做的（创造） | AI 做的（功底） |
|---|---|
| 哪几张是一件事（分组） | 统一纸色、双色、字体、极细线 |
| 给这组起什么名字 | 把字排到不拥挤、不裁字 |
| 哪张不要（取舍） | 直角裁切、留白比例、跨页成对 |
| 谁先谁后（顺序） | 页数凑 4 的倍数、骑马钉页序 |
| 哪张当封面／最后一张 | 渲染 HTML/PDF、拼版 |
| 这页写哪句话、原话不动 | 把她的决定落盘、可复现 |
| 哪页干脆空着 | 打印设置说明 |

**关键：每个决定都要看得见因果。** 不是最后才出 3 页样张，而是改一次分组就刷新卡片墙，改一句话就刷新那一页。
她看到「我把 06 挪到 03 旁边，这页忽然对了」——这个瞬间就是乐趣。

---

## 三、反访谈三原则（让聊天像人，不像表单）

1. **先摊开，不先提问。** AI 先给一份**可推翻的草稿**：「我看下来像是海边傍晚 / 草地野餐 / 一顿饭，分错了你直接改」。
   不要上来列 10 个问题，也不要把分组当结论。
2. **一次只搭一句话，不问「请提供文案」。** 聊的是事情，不是文字：
   「那天跟谁一起？」「有没有没拍下来、却还记得的小事？」「这张旁边放那张好像更对，你觉得呢？」
   她随口说的原话直接留下，不追问、不扩写、不要求完整句子。
3. **允许跳过、含糊、反悔。** 「先这样吧」「这页不放字」「说不上来，但别放那张」都是合法输入。
   有表达欲的人最烦被流程逼着填表；任何一步都能说「这题跳过」。

**AI 的位置是旁边看她翻照片的朋友，不是拿提纲的编辑。**

---

## 四、限制本身就是乐趣

zine 的乐趣很大一部分来自**边界**：纸就这么多页、一张图只能用一次、一页只能写一句话。
所以不是给她无限自由，而是给她**有边界、有后果、可反悔的选择**：
- 一张图全本最多 2 次，第二次必须换裁切或角色并标注（AP-4，v1 回退后放宽）
  → 她仍然要真的挑「哪张才配占这一页」
- 页数由素材量决定，缺页用留白补 → 她必须决定「哪里该喘口气」
- 同一场景的照片必须相邻 → 她必须决定「这几张算不算一件事」

这三条同时是 `anti-patterns.md` 的硬规则，机制与审美在这里合一。

---

## 五、story.json：人的部分（草案）

`story.json` 与 `plan.json` 并列：**前者是人的决定，后者是机器的排版**。引擎只读，不临场发挥。

```json
{
  "groups": [
    {
      "id": "A",
      "name": "海边傍晚",
      "name_source": "user_verbatim",
      "images": ["02", "08", "13"],
      "note": "那天风很大，我们没等到日落就走了",
      "note_source": "user_verbatim"
    }
  ],
  "order": ["A", "B", "C"],
  "dropped": ["09"],
  "cover": {"image": "08", "layout": "paper_collage", "title": "……", "title_source": "user_verbatim"},
  "back": {"layout": "breath", "text": ""},
  "palette": "A",
  "mood": "安静的日记",
  "confirmed": ["groups", "cover"],
  "pending": ["back", "mood"]
}
```

**来源标记只有三种，必须显式**：
- `user_verbatim`：用户原话，一字不改
- `user_confirmed_guess`：AI 猜的，但已标「我猜的，对吗」并获确认
- `unfilled`：没填，宁可留白也不补

`confirmed` / `pending` 让对话可以中断、下次接着聊，不会丢。
`palette` / `mood` 是保留字段，目前只作对话记录，不驱动排版（见 §八）。

---

## 六、AI 三条红线

1. **不替她写感受、不润色原话。** 错别字、半句话、口语、标点都保留。
2. **不把推测写成事实。** 任何「那天应该是…」「这组像…」都要带「我猜的」，确认前不进 `story.json`。
3. **不替她做取舍而不告诉她。** 自动补页、自动换骨架都要在版式清单里写明「这里我补了一页留白，你可以说换掉」。

## 八、落地状态：`--story` 已经接进引擎了

不是文档草案，`make_zine.py` 已实现并跑通（`--story /路径/story.json`）。

**两种写法都认**：

| 来源 | 长什么样 | 差异 |
|---|---|---|
| `摆台.html`「下载 story.json」 | `cover` / `back` 是字符串、`ungrouped`、`confirmed/pending` 是计数 | 直接用，不用改 |
| 对话草稿（本文件 §五） | `cover` / `back` 是对象、`order` 是组 id 列表、`dropped` 是数组 | 直接用，不用改 |

**引擎实际执行的**：

- 按 `order`（或 `groups` 数组顺序）排版，同一组照片连续出现、不拆散；组内按你写的顺序取图。
- `dropped` / `ungrouped` 不参与；完全没提到的照片补进尾组，保证没有一张整本不露面。
- `cover.image / title / sub / layout`、`back.image / text / layout` 生效：
  `photo_full` / `paper_collage` / `plain` / `breath` / `photo` 都可用。
- `groups[].note` 原样放在该组第一页；已确认的 `name` 变成该组页面的 tiny 标签。
- 标了 `user_confirmed_guess_pending` / `unfilled` 的内容**不印**，只留白。
- `breath` 是你指定的留白页数；为凑 4 的倍数自动补的页，在 `版式清单.txt` 里标〔我补的〕。
- 每张照片全本最多 2 次，第二次换角色并点名；中心跨页用**两张不同的照片**，不是同一张左右复制。
- 额外产出 `文字来源对照.txt`：册子上每个字标出是「你的原话」还是「版式自带的功能性编号」。

**还没做的**：`palette` / `mood` 是保留字段，暂不驱动排版；拖拽换页/换版式的交互产品也还没做。
这两项不影响「先摆 → 排版 → 打印」这条链路。

**已验证**：用 14 张真实照片 + 摆台草稿跑出 8 页（14/14 全用上、单张最多 2 次、
A5 阅读版与 A4 横向打印版尺寸均正确）；另用字段级自检覆盖了两种 story 写法、
封面/封底自定义、原话不改写、待确认不印、指定留白页。
